# SQL construction review (Phase 10.6)

Every SQL statement in Atlas binds its **values** as parameters. This review covers the
remaining risk: statements whose **text** is built with interpolation, where a spliced name
could change the shape of the query.

The inventory is machine-generated by `scripts/audit_sql_interpolation.py` and committed as
`docs/SECURITY_SQL_INTERPOLATION.json`. It walks the AST, keeps only f-strings that begin with a
SQL keyword, and records every interpolated expression.

```
49 interpolated statements
  21  placeholders_only   the interpolation is a run of "?" marks for an IN (...) list
  24  review              static fragments: WHERE clause pieces, column constants, AND-joins
   4  structure_named     a table or column name is spliced
```

## The four statements that splice a name

| Site | Spliced name | Where it comes from | Verdict |
| --- | --- | --- | --- |
| `src/atlas/evidence/kernel.py:619` | `column` | `AsOfMode.column` — a property of a two-member enum | Allowlisted. The mode is parsed with `AsOfMode(str(mode))`, so any other string raises before SQL is built (covered by `test_as_of_mode_can_only_select_an_allowlisted_column`). |
| `src/atlas/evidence/selection_sql.py:242` | `column` | the same `AsOfMode.column` | Allowlisted. Only two constant values exist: `availability_time`, `observed_at`. |
| `src/atlas/mcp/tools.py:498` | `table` | a literal tuple inside `inspect_data_health` | Constant. The tool takes an `arguments` dict, but the table list never reads it (covered by `test_mcp_health_counts_only_its_own_table_list`, which passes hostile `table` and `counts` arguments). |
| `src/atlas/storage/db.py:221` | `table` | a caller-supplied table name to `row_count()` | Guarded. `_SAFE_IDENTIFIER` rejects anything that is not alphanumeric/underscore, and the helper raises `StorageError` (covered by `test_row_count_refuses_anything_but_a_bare_identifier`). |

No other statement splices an identifier. The 24 "review" sites interpolate only:

* **placeholder runs** — `', '.join('?' for _ in wanted)`, paired with a bound parameter list;
* **static clause text** — `' AND '.join(clauses)` where `clauses` is built from literal
  conditions such as `"concept IN (...)"` or `"entity_id = ?"`;
* **module constants** — `_SELECT_COLUMNS`, `_TIER_CASE`, `_QUALITY_CASE`, `COLUMNS`.

Each was read in place. None of them reads a request field, a query string or a tool argument
into the SQL text.

## What is tested

`tests/test_sql_structure_safety.py` (9 tests) attacks the structure layer rather than the value
layer:

* hostile table names through `Database.row_count` (drop statements, comment markers, empty),
* an unrecognised as-of mode, which cannot choose a column,
* hostile MCP arguments to the health tool,
* SQL metacharacter payloads through full-text search (the query is echoed as a value and the
  tables survive), and a query with no indexable terms, which is refused before SQL,
* an unknown concept filter, which is refused rather than spliced.

Value binding is exercised throughout the existing suite: every DAO in `src/atlas` passes a
parameter tuple and no test needed a string-escaping helper.

## Residual risk

* The inventory is a static scan. A future statement built by string concatenation across
  several lines (not an f-string) would not appear in it; `grep` for `+ "SELECT` style code is
  the manual complement.
* A new column, mode or table name must be added to an enum, a constant or the identifier guard.
  The four sites above are the places where that convention is load-bearing.
* This review does not address SQLite's own parser, file permissions on the database, or the
  local API's authentication (there is none; the API is loopback-only by design and is not for
  public deployment).

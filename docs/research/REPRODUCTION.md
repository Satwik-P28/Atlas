# Reproduction

Every number in the technical report is regenerated by three commands. Nothing is hand-edited.

## 1. Environment

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev,terminal,optimization]"
.venv/bin/python -m pip install "osqp>=1,<2" "clarabel>=0.11,<1"
```

`optimization` is the extra that carries SciPy for the decision layer; it is deliberately not part
of `dev`, and the decision tests skip cleanly without it. OSQP and Clarabel are **reference
solvers only** — the certificate never calls them. Install them to run the cross-checks and the
`reference` tests.

Reported run: Python 3.12.3, NumPy 2.5.5, SciPy 1.18.1, OSQP 1.1.3, Clarabel 0.11.1, Linux x86-64.

## 2. Tests

```bash
.venv/bin/python -m pytest -q
```

The decision layer is 98 tests across `tests/test_decision_program.py`,
`tests/test_decision_certificate.py` and `tests/test_decision_certification.py`. The third module
is the adversarial set: negative multipliers, mismatched geometries, infeasible recorded decisions,
iteration budgets, superseded and withdrawn revisions, and worst-case soundness against vertex
enumeration.

## 3. Synthetic experiments

```bash
.venv/bin/python scripts/research/cri_experiment.py --output artifacts/research
```

Deterministic: seeds are fixed in `CONFIG`, nothing reads the clock for a decision, and the dataset
digest is SHA-256 over the exact float64 arrays. Runtime ≈ 41 s.

Outputs:

| file | contents |
|---|---|
| `artifacts/research/cri_results.json` | single machine-readable source for every table |
| `artifacts/research/cri_tables.md` | every published table, rendered from the JSON |
| `artifacts/research/cri_report.md` | identical rendering, kept for continuity with the first revision |
| `artifacts/research/cri_ledger.jsonl` | append-only trial ledger, including rejected trials |

The prose report copies numbers from `cri_tables.md`. If they disagree, the tables are right.

## 4. Real evidence

```bash
.venv/bin/python scripts/research/sec_evidence_case.py --output artifacts/research/evidence
```

Fetches four SEC EDGAR payloads — company facts, submissions, and both primary 10-K documents —
and caches the exact bytes next to the outputs with their SHA-256 digests. The primary documents
are what the case study's accounting characterisation is read from: the Item 9C error-correction
checkbox and the recast disclosure sentences, both recorded verbatim in the JSON alongside each
document's digest, URL and byte count.

Without network access it replays from the cache and records `served_from_cache: true` in the JSON,
so a reviewer can tell which run they are looking at. **The two API payloads are committed**
(`concept.json`, `submissions.json`, ~1 MB); **the two 10-K documents are not** (11 MB of HTML), so
a fresh clone fetches those once and verifies them against the digests in
`sec_evidence_case.json`. The quotes and the checkbox state are in the committed JSON either way,
so the accounting characterisation can be read and re-checked without holding the filings.

The script checks the archive's current values against the accession numbers it expects and refuses
to proceed if the later figure has disappeared — an archive can be revised again, and the case
study should fail loudly rather than silently compare a figure with itself. The same guard applies
to the characterisation: if a filing's Item 9C box ever reads as checked, the script reports
`error_correction` rather than the recast label, so the verdict follows the documents.

## 5. What is *not* reproducible

Wall-clock timings (`§6.8` of the report) are machine-dependent. Everything else, including the
bootstrap intervals, is seeded.

## 6. Verifying the claims independently

| claim | how to check it |
|---|---|
| The bound is sound | `bound_sound_at_*` arms in `cri_tables.md`; zero violations across 598 events and seven budgets. |
| The exact certificate is correct | `test_three_independent_solvers_agree_to_machine_precision`, `test_primary_solver_matches_the_independent_reference`, `test_osqp_and_clarabel_both_reach_the_exhaustive_optimum_on_random_problems`. |
| The inequality has the right direction | `test_weak_duality_has_the_documented_direction`, `test_the_bound_is_an_upper_bound_on_realized_regret_not_a_lower_bound`. |
| Invalid dual points are refused | `test_negative_multiplier_is_refused_and_its_false_bound_is_exhibited` — it also exhibits the negative "bound" the old code would have reported. |
| The iteration budget is honoured | `test_the_iteration_budget_is_the_budget_that_runs[0..200]`. |
| The residual certificate is an identity | `test_residual_bound_satisfies_its_identity_and_bounds_the_gap`. |
| A revision already in the vintage is not re-applied | `test_revision_before_the_decision_clock_is_not_applied_again`, plus the SEC double-count control. |
| The worst-case bound is sound | `test_interval_worst_case_bound_covers_every_vertex` and the 40-trial enumeration experiment. |
| The worst-case bound is not exact | `test_out_of_set_corrections_are_measured_not_hidden` and the 87.5% out-of-set violation rate. |

## 7. Regenerating the report's tables

```bash
diff <(sed -n '/## Trial accounting/,$p' artifacts/research/cri_tables.md) \
     <(sed -n '/### 6.2/,/## 7/p' docs/research/ATLAS_CRI_TECHNICAL_REPORT.md)
```

This will not be identical — the report reformats tables for prose — but any *number* that appears
in the report and not in `cri_tables.md` is a bug in the report. That check is the reason the stale
25.6× figure cannot recur.

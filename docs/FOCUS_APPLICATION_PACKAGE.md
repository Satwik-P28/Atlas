# FOCUS Application Package

Short, defensible statements for applications, portfolios and interviews. Every claim maps to a file,
a test or an artifact in this repository.

## One-line description

Built a point-in-time financial research system that binds historical SEC evidence to typed
computations, preserves unresolved source metadata, and emits certificates that can be checked
against pinned source snapshots.

## Problem statement

Financial answers are unreliable in a specific, boring way: the number is real but its context is wrong.
The filing says `34,229`, the reader assumes units, and the answer is off by six orders of magnitude while
looking precise. Atlas records statement identity, reporting period, scale, currency when available,
and modelled availability, refusing when required evidence is unresolved.

## What was built

- **Ingestion with availability semantics.** SEC 10-K HTML is stored with exact bytes, a digest and an
  EDGAR acceptance timestamp, so "was this public at the cutoff?" is answerable.
- **Cell-level extraction that abstains.** A flattened-row reader records period, scale, source
  coordinates and optional currency; unknown required scale is recorded as unknown rather than zero.
- **Evidence binding.** A resolved cell is frozen into a typed binding (digest, coordinates, raw text,
  period, scale, currency) so downstream arithmetic cannot silently re-select a different row.
- **Two independent arithmetic implementations.** The compiler and a `Fraction` verifier must agree.
- **Research certificates.** Canonical JSON with a fingerprint over the body, typed precision and an
  economic amount derived from the printed value and the scale.
- **A four-level verifier.** `SOURCE_VERIFIED`, `ARITHMETIC_VERIFIED`, `SOURCE_UNVERIFIED`, `INVALID`,
  from two passes that are not allowed to help each other.
- **A trust anchor that is external to the artifact.** A pinned manifest plus archived source bytes,
  generated by an explicit command, never regenerated during verification.

## The result that matters

Twenty-nine forged certificates were constructed by mutating a valid one and recomputing its
fingerprint, so each forgery is internally consistent. All twenty-nine were refused. The decisive case
changes both the printed input and the computed result: it passes independent arithmetic and is caught
only by comparison against the pinned manifest and archived bytes. Thirteen further forgeries leave
every binding authentic and only relabel the displayed answer or the normalized requirement; those fail
before any evidence is consulted. That is the argument for keeping arithmetic verification and source
verification separate instead of treating one as a proxy for the other.

## Honest scope

- Thirteen real-filing cases: ten answered, three refused for three different reasons.
- One of those refusals is a **capability gap**, not a success: the 3M FY2018 filing prints consolidated
  net sales of `32,765` and Atlas does not resolve it. It is reported as a refusal with the observed value
  attached so it cannot be counted as an answer.
- `SOURCE_VERIFIED` means consistent with a pinned snapshot. It does not prove publication time, financial
  semantic correctness, or manifest authenticity, and the docs say so in those words.

## Engineering signals

| Signal | Evidence |
|--------|----------|
| Refuses rather than guesses | abstention paths in `financial_concepts.py`, `financial_answers.py`; 3 refusal classes |
| Verifies rather than asserts | `certificate_verify.py`, 29/29 mutations refused |
| Binds the displayed answer too | `result.period`/`currency`/`unit` reconciled with bindings; `value_exact` mandatory |
| Repairs root causes | scale read from the header row, not the data row; unknown scale is `None`, not `0` |
| Keeps trust external | circular `trusted_sources` replaced by manifest + bytes; legacy callers get `SOURCE_UNVERIFIED` |
| Fail-closed CLI | demo exits `0`/`1`/`2`; missing evidence reported, never manufactured |
| Test discipline | 812 backend tests, 50 frontend tests, adversarial matrix parametrized |
| Reproducibility | archived bytes, pinned manifest, `verify_clean_install.py` reproduces packages offline |

## Repository map

`src/atlas/research/` (certificate, verifier, resolution, answers, cases), `scripts/` (corpus, manifest,
demo, reproduction), `tests/` (levels, mutations, fetch limits), `docs/` (technical note, architecture,
results, source rights, release report).

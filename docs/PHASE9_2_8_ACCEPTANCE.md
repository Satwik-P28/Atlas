## 4. Markets Overview N+1 bottleneck — removed, with proven equivalence

`src/atlas/terminal/market_projection.py` implements
`atlas.market_overview.bulk.v1` as an **execution plan for the unchanged selection contract**,
not a second pricing policy. `market_overview(db, projection="bulk"|"scalar")` dispatches to
it; the previous per-security loop is retained verbatim as `market_overview_scalar` and is the
reference implementation.

Plan shape (constant `PROJECTION_QUERIES = 9` statements per request, independent of universe
size): one identity/ticker resolution, one bulk session calendar, one bulk corporate-action
read, one bulk bar scan streaming all securities ordered by security and session, then batched
source/metadata lookups. Revision resolution happens in Python over the streamed rows, which
removes the previously correlated per-row subquery; `ts_utc BETWEEN a||'T00:00:00Z' AND
b||'T23:59:59Z'` keeps the index usable, where `substr(ts_utc,1,10)` had defeated it.

One shared shortcut was added to `series_changes`: when `split_adjusted` is requested and no
corporate actions exist, raw closes are used, because the adjustment factor is exactly
`Decimal(1)`. A test pins that identity.

### Measured (2 vCPU, warm, median of repeated calls in one process)

| Securities | Plan | Latency | SQL statements | Peak traced memory |
| --- | --- | --- | --- | --- |
| 100 | scalar | 432.7 ms | 1,202 | 1.24 MB |
| 100 | bulk | 430.5 ms | **9** | 0.96 MB |
| 1,000 | scalar | 4,829.6 ms | 12,002 | 3.95 MB |
| 1,000 | bulk | 4,294.3 ms | **9** | 5.05 MB |

Statements fall by **133.6×** at 100 securities and **1,333.6×** at 1,000, and the count no
longer grows with the universe. Latency improves 1.01× and 1.12×: the bottleneck was never
the statement count, it is per-point materialisation of ~260,000 observations at roughly
16–25 µs each, with SQL itself taking ~1.4 ms.

**The sub-second 1,000-security target is not met** (4.29 s measured). The frontier is
declared rather than assumed: reaching it requires a SQL-side windowed projection or a
reduced point set, and both would either duplicate the selection contract or drop returned
functionality, so neither was taken in this checkpoint. No Redis, second database or
distributed compute was introduced, and no securities or calculations are omitted to gain
speed.

Peak memory for the 1,000-security bulk plan is 5.05 MB against 3.95 MB scalar; the higher
figure is reported, not hidden.

## 8. Flagship workflow (Section 59.1) — status map

Steps working in the UI: choose a company, inspect original evidence, save a thesis
(workspace). Partial: reconcile statements, run scenarios, challenge assumptions and
coverage. API/script only: configure an arbitrary model. Unsupported: export a professional
artefact, monitor evidence changes for a saved thesis.

The smallest missing component is the **grounded research artefact**: the workflow ends
inside the application, so nothing can be monitored. Recommended next milestone: export a
report whose every claim, number and citation resolves to a stored evidence, observation or
model-version id, bind it to the saved workspace, and mark it stale with the affected items
when a new revision arrives. Details in `docs/MASTER_SPEC_V3_IMPLEMENTATION_GAPS.md`.
